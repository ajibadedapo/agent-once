Stop your AI agent from charging, booking or sending twice.

# agent-once

When an agent's tool call times out or its response is lost, the agent cannot tell whether the order was placed, the slot booked or the email sent. It usually tries again, and the side effect happens twice. agent-once sits between the agent and the tools that change the world. It gives every side-effecting call a stable identity, records it in a local ledger before it runs, and on a repeat either returns the recorded result, checks what really happened, or stops and asks. It works as a drop-in MCP proxy for any MCP client (Claude Code, Claude Desktop, Cursor, the Claude Agent SDK), as a TypeScript and Python library, and it ships a chaos suite that proves the protection on your own agent in CI.

## Quick start

Wrap the Playwright MCP server in Claude Code:

```bash
claude mcp add playwright -- npx agent-once mcp -- npx @playwright/mcp@latest
```

For Claude Desktop (`claude_desktop_config.json`) or Cursor (`.cursor/mcp.json`), put `agent-once mcp --` in front of the server command:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["agent-once", "mcp", "--", "npx", "@playwright/mcp@latest"]
    }
  }
}
```

That is the whole setup. No config file, no account, no network calls of its own. Every tool works as before. When a guarded click such as "Place order" fails or times out and the agent tries it again, agent-once does not repeat it: it checks the page if you configured a read-back, asks you through the client (MCP elicitation) if the client supports it, or returns a clear result telling the agent not to retry. A person can settle any doubt from a terminal:

```bash
npx agent-once ledger list --in-doubt
npx agent-once resolve ao_0123456789abcdef01234567 --happened
```

The ledger lives in `~/.agent-once/ledger.db` (or `$AGENT_ONCE_HOME`). On Windows, wrap the inner command as `-- cmd /c npx @playwright/mcp@latest`, because agent-once starts the server without a shell. See [docs/getting-started.md](docs/getting-started.md) for the walkthrough.

## The guarantee

agent-once promises at most once by default, exactly once wherever a reconciler can confirm the outcome.

- **At most once by default.** A call whose outcome is unknown (sent, no answer, or an error or timeout inside the 120 s retry window) is never repeated silently. The guard reports the doubt instead of dispatching again.
- **Exactly once with a reconciler.** When you configure a read-back (a read tool or page that shows whether the effect landed), the guard checks it: if the effect happened it returns the recorded outcome, if it did not it runs the call.
- **Money and irreversible actions block.** Tools whose name or label matches pay, buy, checkout, purchase, charge, order, payment or transfer (money) or delete, publish, send or deploy (irreversible) default to `block-on-doubt`: only a person (elicitation, the approval webhook or `agent-once resolve`) can release them. Everything else the guard covers lets the agent check and record the answer with the `agent_once_resolve` tool.
- **Deliberate repeats still work.** A call that succeeded and is repeated later in the same run runs again. A rerun of a crashed run within the retry window, or within 24 h with an explicit session, replays the recorded result instead.

[docs/how-it-works.md](docs/how-it-works.md) has the full decision table.

## What it cannot see

- **The browser's own traffic.** The proxy sees MCP tool calls, not the HTTP requests a browser sends to a remote site. A lost response between the browser and the site is detected from the page (error markers, success markers and optional read-back), not from the network.
- **MCP has no idempotency field.** `tools/call` carries no idempotency key, so a remote API reached through an MCP server cannot deduplicate on its own. agent-once forwards its key in `_meta["io.github.ajibadedapo/agent-once-action"]` for servers that want it, and the TypeScript `guardedFetch` sets an `Idempotency-Key` header on direct HTTP calls.
- **Known limitation: connection reset after commit.** When a server commits a form POST and then drops the connection, Chromium re-sends the POST by itself, below the MCP layer. The server sees two submissions from one click. agent-once cannot see or stop this: the benchmark measured 12 duplicates in 12 runs with and without the guard. The fix belongs on the server: deduplicate a resubmitted form, for example with a one-time form token, or accept an `Idempotency-Key` where the request comes from code.
- Remote (HTTP or SSE) MCP servers are not wrapped in this release; only stdio servers are.

## TypeScript

```bash
npm install agent-once
```

```ts
import { randomUUID } from 'node:crypto';
import { homedir } from 'node:os';
import { Guard, JsonlEvidenceSink, SqliteLedgerStore, defaultLedgerPath, systemClock } from 'agent-once';

const store = SqliteLedgerStore.open(defaultLedgerPath(process.env, homedir()), systemClock);
const guard = new Guard({ store, clock: systemClock, runInstance: randomUUID(), evidence: new JsonlEvidenceSink('agent-once-events.jsonl') });

const placeOrder = guard.wrap(
  { tool: 'place_order', sessionKey: 'order-run-42', sessionExplicit: true, policy: 'block-on-doubt', toolClass: 'money' },
  async (args: { item: string; qty: number }) => {
    const response = await fetch('https://shop.example.com/api/orders', { method: 'POST', body: JSON.stringify(args) });
    return { status: response.status };
  },
);

await placeOrder({ item: 'Blue mug', qty: 1 });
```

A repeat of an in-doubt call throws `ActionInDoubtError` instead of placing a second order. Node 22.13 or later is required (the ledger uses `node:sqlite`). Loading the ledger wraps `process.emitWarning` for the life of the process to drop Node's ExperimentalWarning about `node:sqlite`; every other warning passes through. More in [docs/typescript.md](docs/typescript.md) and [docs/claude-agent-sdk.md](docs/claude-agent-sdk.md).

## Python

```bash
pip install once-guard
```

```python
import os
import uuid

from agent_once import Guard, JsonlEvidence, SqliteLedgerStore, SystemClock, default_ledger_path

clock = SystemClock()
store = SqliteLedgerStore.open(default_ledger_path(os.environ, os.path.expanduser("~")), clock)
guard = Guard(store, clock, str(uuid.uuid4()), JsonlEvidence("agent-once-events.jsonl"))


@guard.tool(policy="block-on-doubt", tool_class="money", session_key="order-run-42")
def place_order(item: str, qty: int) -> dict[str, object]:
    return {"order": "ORD-1", "item": item, "qty": qty}


place_order("Blue mug", 1)
```

The PyPI distribution is `once-guard`; the import name is `agent_once`. Both cores read and write the same ledger format ([spec/ledger-v1.md](spec/ledger-v1.md)). More in [docs/python.md](docs/python.md).

## Chaos and CI

The chaos suite runs an agent against four reference targets (checkout, booking, email, ticket) with injected faults and counts real duplicate and missing effects from each target's ground truth:

```bash
npx agent-once chaos run --guard both --fail-on-duplicates
```

Bring your own agent with `--agent "<command>"`, or run it in GitHub Actions with the bundled action. There are vitest matchers (`agent-once/vitest`) and pytest fixtures (`once_guard`, `agent_once_chaos_targets`) for your own tests. See [docs/chaos.md](docs/chaos.md) and [docs/ci.md](docs/ci.md).

## How it compares

agent-once is a proxy plus a chaos suite: it protects any MCP client and browser agent without code changes, and it measures the protection on your own agent. Libraries such as [frogscooper/once](https://github.com/frogscooper/once) wrap Python functions with an idempotency key and suit code you control. Temporal owns durable execution of whole workflows; agent-once does not replace it and guards individual tool calls.
